# Geez Squad bug audit — 22 October 2026

This audit covers account entry, member-to-account linking, studio operations, financial writes, live participation, conference lifecycle, data export, diagnostics and deployment readiness. Passing automated checks is not a claim that all possible defects are eliminated.

| Priority | Confirmed defect | Resolution |
| --- | --- | --- |
| P1 | Members and coaching access required separate workflows | Durable in-app requests, verified acceptance, stable account links |
| P1 | Contact email controlled which account saw member history | Financial/history reads use stable user ID |
| P1 | Broad auth catches disguised operational failures as failed login | Redirect only expected authentication states; propagate operational failures |
| P1 | Request IDs were discarded; non-JSON failures broke error handling | Typed client errors, correlation headers, visible support references |
| P1 | Error logs lacked route/operation context | Structured, level-filtered, allowlisted logs across API/auth/email boundaries and server rendering |

## Verification

Initial baseline: 338 unit tests and TypeScript passed despite the issues above. New regression coverage exercises account-link ownership, verification gates, delayed signup, acceptance retries, contact edits, decline/resend/withdraw, term selection, logger redaction, client error parsing, SMTP failures and independent device setup. Current verification: 357 unit tests, TypeScript, 179 authentication/access API checks, 68 studio-operation API checks, and all 47 browser tests passed. Browser coverage includes automated accessibility, 320/390px authentication, persisted onboarding, studio CRUD, galleries up to 48 trainees, camera recovery, live controls and historical saves. An eight-member concurrent HTTP rehearsal completed 51 requests with zero failures; it does not measure WAN or WebRTC capacity. The optimized Next.js production build passed.

PostgreSQL migration rehearsal passed in an isolated temporary schema, preserving legacy credentials/sessions and checking stable-link uniqueness, account-deletion history retention and cascade behaviour. No real user data was copied into rehearsal fixtures.

## Practical limits

- Gmail is a free, quota-limited sender. Successful SMTP acceptance does not guarantee inbox placement; actual verification and recovery delivery must be tested.
- Live expiry enforcement depends on polling/actions and available room services. It is not an instantaneous scheduler.
- Existing clients with no valid term must be assigned real membership dates before participation; backfill never invents payments or terms.
- Studio operation reads still load historical rows as a batch. Pagination remains a future scaling improvement.
- This phase does not add paid billing enforcement, staff login permissions, payroll, GST invoicing or automatic renewals.

## Production impact before migration

Read-only assessment: 5 accepted coaching clients, 3 existing physical member records, 2 unambiguous links, 3 new member records required, zero conflicts, 3 clients without active terms, and 5 sessions marked live. Enabling the selected access policy will prevent those 3 clients from participating until a real membership is assigned. No terms or payments will be fabricated. Production migration/backfill and release remain subject to the specific automatic-approval requirement; SMTP delivery is tested after the staged release is available.
