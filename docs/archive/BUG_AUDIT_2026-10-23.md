# Geez Squad roles, member access and workout feedback

This release keeps Better Auth credentials and Gmail delivery, introduces studio-scoped Admin, Coach and Trainee permissions, and makes member account connection and workout completion explicit.

## Data preservation and cutover

The additive SQLite and PostgreSQL migration creates role grants, coach requests, current assignments and assignment history; adds nullable host/author/request-target fields; and backfills exact existing owners and accepted memberships. It does not change passwords, sessions, user profiles, verification flags, membership dates, payments or attendance. Existing directory entries receive no staff privileges.

Both database rehearsals preserve legacy credential/session fixtures, verify owner/trainee grants and host identities, and reject privilege inference from directory titles. `scripts/backfill-studio-roles.mjs` is idempotent: it fills missing legitimate legacy grants but never activates an existing revoked/suspended grant. Legacy member access also requires the accepted membership record, so a removed membership cannot retain access merely through a stale grant.

Read-only production assessment before migration: 6 studio owners, 5 accepted trainees, zero studio conflicts, zero missing stable member links, 5 unassigned trainees, 3 clients without valid membership terms, and 5 sessions marked live. Unassigned trainees remain manageable by their studio admin. Real membership terms must be assigned to the three affected clients; no terms or payments are fabricated.

## Verification evidence

The local baseline passed 366 unit tests, 179 authentication/access/lifecycle API checks, 68 studio operations/financial checks, and 111 role/assignment/restore/booking checks. Disabled-email and test-email modes passed 9 and 28 checks in disposable databases. All 30 standalone accessibility checks passed. Browser coverage includes all three roles, real API persistence, mobile Team controls, assigned walk-ins, account connection, booking/cancellation, capacity, automated accessibility, automatic and early set completion, zero-rest explicit starts, pause/tracking loss and save retry without duplicate records.

The first full browser pass exposed two fixture navigation races; explicit navigation/readiness waits fixed them. A separate overlapping diagnostic run caused a trace-file collision; affected journeys passed when run sequentially with isolated outputs. Production promotion remains gated on the final CI and staged checks, recorded in the release evidence.

Three new controlled release accounts received real Gmail verification emails, and the mailbox owner confirmed opening all three links. Read-only inspection confirmed all three verification flags were set by the actual verification flow. Test passwords/tokens are kept in ignored local release state and are never logged or committed.

## Practical limits

- This phase does not add payroll, tax invoices, automatic renewals or differentiated plan entitlements.
- Revocation/expiry cleanup uses actions and polling; it adds no independent real-time scheduler. RTC cleanup failures are logged and retried.
- Automated browser checks cover synthetic movement/media and deterministic permission failures. Physical-device movement accuracy, Safari/mobile hardware variations and long WAN calls still need field testing.
- Historical studio lists are bounded or loaded in batches; high-volume pagination remains future scaling work.

## Navigation and returning sessions follow-up

The workspace menu previously mixed front-desk tasks, coaching and administration in one long list. Role-specific groups now put daily work first; a scrollable menu keeps Settings, Help and the account control reachable on short screens. Four role-specific mobile shortcuts provide direct access to common pages. Camera practice and live meetings retain their existing control space, and notifications sit above the mobile shortcuts.

The login page previously rendered a sign-in form without checking a valid session. It now validates the session on the server and redirects to the app or a preserved, safe shared-session/invitation destination. Missing or expired sessions retain sign-in, verification requirements remain distinct, explicit password-reset links stay usable, and database/provider failures propagate to the error boundary. Regression coverage includes forged cookies, unsafe and repeated destinations, all three role menus, mobile navigation and short landscape screens.
